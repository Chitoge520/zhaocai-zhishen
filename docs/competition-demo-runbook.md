# 招采智审比赛现场演练手册

## 1. 赛前准备

在项目目录打开 PowerShell：

```powershell
Set-Location "<项目目录>"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q src
.\run.ps1 serve
```

浏览器访问：

```text
http://127.0.0.1:4180
```

比赛前确认：

- `data/models/bid_anomaly_model.json` 存在；
- `data/analysis/analysis_summary.json` 存在；
- 浏览器可以打开首页；
- 不在现场首次执行 OCR 或训练；
- 大模型不可用时，本地异常线索页面仍然可以正常展示。

## 2. 推荐演示顺序

### 第一步：项目总览

点击“加载离线演示”，展示真实历史预计算结果。重点展示数据规模、GPU OCR 状态、项目内比较数和待复核线索数。

建议表述：

> 系统把历史投标项目整理成可追溯的文档和证据索引，现场展示使用预计算结果，不依赖临时训练或网络调用。

### 第二步：异常线索

进入“异常线索”，选择一条中风险线索。强调异常分数用于排序，不是违规概率。

### 第三步：关系图谱

进入“关系图谱”，展示项目、投标人、文件和共享实体之间的关联。点击或说明红色相似关系，强调图谱是审计入口。

### 第四步：双栏证据回放

从线索进入“双栏证据回放”，切换双方页码，展示双方原文片段、共同实体和引用位置。

建议表述：

> 评委看到的不是一个不可解释的风险分数，而是可以回到双方原始页面的证据链。

### 第五步：报告导出

进入“项目报告”：

- 点击“导出 DOCX”下载 Word 报告；
- 点击“打开 HTML 打印版”，在浏览器中选择打印并保存为 PDF。

不要说“系统直接生成 PDF”，除非现场已经配置并验证了 PDF 生成依赖。

### 第六步：新项目入口

进入“新项目分析”，上传新的 ZIP。展示任务状态从排队到整理、GPU OCR、异常分析、冻结模型推理和大模型辅助复核的阶段变化。

## 3. 大模型配置

在“大模型配置”页面输入密钥并应用。页面只显示“已配置”，不会回显密钥。

默认 API 地址为：

```text
https://api.deepseek.com
```

现场建议：

- 只在需要演示大模型辅助解释时启用；
- 提前用一条小任务验证网络和额度；
- 不把密钥写入代码、截图、PPT 或报告；
- 如果网络不可用，关闭大模型，继续展示本地分析、关系图谱和证据回放。

## 4. 故障排查

### 首页打不开

确认服务是否启动：

```powershell
Get-NetTCPConnection -LocalPort 4180 -State Listen
```

如果端口被占用，先停止旧服务，或修改配置端口后重新启动。

### 离线演示没有数据

检查以下文件：

```text
data/analysis/analysis_summary.json
data/processed/summary.json
data/training_internal/summary.json
data/models/bid_anomaly_model.json
```

现场应优先使用已准备好的演示数据，不临时运行全量 OCR。

### 新任务失败

进入任务列表查看阶段和错误信息；查看：

```text
data/jobs/<job_id>/error.log
data/jobs/<job_id>/status.json
```

典型原因包括压缩包没有投标文件、文件超出安全限制、OCR 依赖缺失或冻结模型不存在。

### 大模型失败

本地规则和冻结模型结果不受影响。报告中会标记大模型状态，演示时转入证据回放并说明系统具备降级能力。

## 5. 对评委的准确表述

可以说：

- 系统采用无监督异常排序，不要求比赛现场人工标注；
- 系统融合文本相似度、共同实体、项目边界和页码证据；
- 大模型用于辅助解释，且其引用必须经过本地证据校验；
- 结果可回放、可导出、可复核。

不要说：

- “模型可以直接认定串标围标”；
- “异常分数就是违法概率”；
- “准确率、召回率已经达到某个数值”，除非有独立、可复现、带版本的数据评测；
- “大模型看过全部投标文件”，系统实际只发送脱敏后的候选证据片段。
