# 招采智审竞赛优化开发计划

> 版本：v1.0  
> 制定日期：2026-08-10  
> 适用赛题：AI+招投标穿透审计——打造“全样本智能筛查+异常行为图谱”系统

## 1. 计划目标

在保留现有 OCR、无监督文本异常、证据页码回放、关系图谱、报告导出和隐私保护能力的基础上，把项目从“投标文件异常审查原型”升级为“多源招投标全样本穿透审计系统”。

本轮优化必须重点补齐赛题明确要求的三类核心能力：

1. IP、设备、账号和文件元数据关联；
2. 投标总价及分项报价聚类、规律性差异识别；
3. 投标人跨项目共现、固定组合和轮流中标分析。

最终形成以下完整闭环：

```text
多源数据导入
→ 全样本特征计算
→ 项目内异常检测
→ 跨项目团伙发现
→ 风险融合排序
→ 异常行为图谱
→ 原始证据回放
→ 审计报告导出
→ 人工复核反馈
```

系统输出始终定位为“待复核异常线索”，不直接认定串标、围标或违法违规。

## 2. 当前基线

截至 2026-08-10，项目已经具备：

- 63 份投标文件全量解析和 OCR；
- 13,732 页、原始 OCR 7,872,221 字符、清洗后分析文本 7,450,481 字符、0 失败的历史处理产物；
- 项目内字符级 TF-IDF 文本相似度；
- 电话、邮箱、统一社会信用代码、联系人和地址提取；
- 公共模板排除和非公共重复片段证据；
- 项目级异常线索、页码定位和双栏证据回放；
- 项目内关系图谱；
- 冻结无监督基线模型和新项目推理；
- 2,100 条、14 类受控变换的合成回归基准；
- ZIP 上传、后台任务、任务取消和失败隔离；
- HTML/DOCX 报告导出；
- 大模型脱敏证据辅助解释和本地引用校验；
- M0 验收时 46 项单元测试通过。

当前核心不足：

- “全样本”主要指投标文件，还没有覆盖完整业务事件；
- 正式分析链路没有真实生成 IP、设备、账号、作者和报价模式特征；
- 图谱按项目隔离，无法发现跨项目固定投标组合；
- 没有报价聚类、轮流中标、共现 Lift 等核心指标；
- 真实项目缺少独立复核测试集，不能报告真实准确率；
- README、历史模块报告和实际产物存在少量数字口径漂移；
- 当前目录尚未形成有效 Git 版本基线。

## 3. 竞赛目标和验收指标

### 3.1 产品目标

比赛版本应能完成两类分析：

- 单项目穿透：从项目进入投标人、文件、报价、IP、设备、账号和共享实体证据；
- 跨项目穿透：从投标人组合进入历史共同投标、共同 IP、报价规律和中标轮换。

### 3.2 最低竞赛验收指标

| 指标 | 最低目标 |
| --- | --- |
| 历史项目扫描覆盖率 | 100% |
| 输入记录可追溯率 | 100% |
| 项目内应比较组合覆盖率 | 100% |
| 风险线索证据引用覆盖率 | 100% |
| IP/设备信号 | 至少支持 3 类规则 |
| 报价信号 | 至少支持 6 类指标 |
| 跨项目共现信号 | 至少支持 5 类指标 |
| 图谱视图 | 项目证据图 + 全局行为图 |
| 报告 | 包含风险摘要、指标、图谱和原始引用 |
| 自动化测试 | 新增模块关键路径全部覆盖 |
| 演示降级能力 | 无网络、无大模型时核心流程可用 |

### 3.3 比赛展示指标

首页需要新增：

- 纳入项目数；
- 纳入投标人次；
- 文件、报价和网络日志覆盖率；
- 项目内比较组合总数与完成数；
- 跨项目投标人关系数；
- 高、中、低风险项目数；
- 建议人工复核项目占比；
- 证据可回溯率；
- 人工首轮检查范围压缩比例。

演示或合成数据产生的指标必须明确标记为“演示测算”或“受控基准”，不得冒充真实业务成效。

## 4. 开发原则

1. **无监督优先**：不以大规模人工标注作为首要前置条件。
2. **多信号组合**：单一 IP、地址或高相似度不能直接定性。
3. **项目隔离训练**：训练、验证和测试按项目划分，禁止文档级随机拆分。
4. **证据先于分数**：每个风险贡献都必须能回到原始记录、文件或页码。
5. **全链路本地化**：真实投标文件默认只在授权本地环境处理。
6. **大模型非核心依赖**：大模型只负责辅助解释和报告草拟。
7. **先补赛题能力再重构技术栈**：比赛前不进行无必要的微服务或数据库大迁移。
8. **合成基准与真实评估分离**：合成指标只用于功能响应验证。
9. **可降级演示**：OCR、模型、图谱、报告均准备预计算结果。
10. **敏感数据最小暴露**：日志、截图、PPT和仓库不得包含真实敏感字段。

## 10. 风险与缓解措施

| 风险 | 缓解措施 |
| --- | --- |
| 没有真实 IP 日志 | 提供标准导入模板和脱敏演示数据，明确演示边界 |
| 报价表格式复杂 | 先支持总价和标准 CSV/Excel，再逐步扩展 PDF 表格 |
| 历史项目数量少 | 使用无监督冷启动，合成数据只做回归，不宣传真实准确率 |
| 共现指标被偶然样本放大 | 设置最小共同项目数、置信区间和低基数警告 |
| 公共出口 IP 误报 | 建立公共 IP 白名单，并要求时间/设备/账号等信号佐证 |
| 图谱过于复杂 | 默认展示高风险子图，支持项目、关系类型和时间筛选 |
| 大模型现场不可用 | 使用本地预计算结果，核心流程不依赖外部网络 |
| 敏感信息泄露 | 脱敏演示快照、日志最小化、Git 忽略和发布扫描 |
| OCR 耗时过长 | 比赛现场只用预计算结果，新项目上传只做小样例 |
| 数字口径不一致 | 单一 summary 数据源驱动 README、页面和报告 |

## 11. 完成定义

一个模块只有同时满足以下条件才算完成：

1. 正式分析链路可以生成结果；
2. 结果包含数据来源和算法版本；
3. 异常能回到原始文件、页码或业务记录；
4. 有正常、异常和边界测试；
5. 页面或报告能够展示；
6. 不泄露真实敏感数据；
7. 无数据时能够安全降级；
8. 文档、接口和实际产物口径一致。
