# 招采智审数据收集清单

## 一、收集单位

数据必须按“完整项目”收集，不能把单份 PDF 当成一个独立训练样本。同一项目的招标文件、全部投标人文件、开标报价和复核结果应放在一起。

建议目录：

```text
项目编号_项目名称/
  项目信息.json
  招标文件/
  投标文件/
    投标人A/
    投标人B/
    投标人C/
  开标与报价/
  评审材料/
  复核结论/
```

## 二、必须收集

每个项目至少需要：

1. 项目编号、项目名称、采购方式、开标日期。
2. 招标文件或采购文件。
3. 至少两个不同投标人的完整投标文件。
4. 投标人名称及其技术标、商务标、报价标的归属关系。
5. 开标记录或最终报价汇总。
6. 文件原始格式，尽量不要只保留打印扫描件。
7. 项目级复核状态：正常、存在异常线索、确认可疑、信息不足或未知。

只有一个投标人的项目可用于文件解析训练，但不能用于项目内串标围标关联训练。

## 三、强烈建议收集

1. Excel 报价明细、分项报价和最终报价。
2. PDF/DOCX 原始文件，保留作者、创建时间、修改时间和生成软件信息。
3. 澄清文件、补遗文件、废标说明和评标报告。
4. 每条已知异常对应的投标人、文件、页码和依据。
5. 人工复核后被排除的误报线索。
6. 同一批供应商在不同历史项目中的共同投标记录。

## 四、最有价值的异常案例

优先寻找具有以下一种或多种情况的已复核项目：

- 不同投标人共享电话、邮箱、联系人、地址或银行信息。
- 不同投标文件存在相同罕见错别字、共同缺项或相同异常排版。
- 多份文件具有相同作者、编辑者、生成软件或接近的创建时间。
- 报价呈固定比例、异常接近、规律性梯度或明显陪标结构。
- 技术响应大段相同但企业名称被替换。
- 多家投标人长期共同出现且中标关系异常。
- 已被审计、投诉、监管或司法材料确认存在异常的项目。

## 五、复核记录最小字段

每个项目至少记录：

- project_id：项目编号
- project_name：项目名称
- review_status：正常、确认可疑、信息不足、未知
- involved_bidders：涉及的投标人
- clue_types：异常类型
- evidence_files：证据文件
- evidence_pages：证据页码
- review_basis：复核依据
- reviewed_at：复核日期
- reviewer_role：复核人员角色，不需要填写真实姓名

## 六、数量建议

当前 15 个历史项目可以训练无监督基线，但不能证明准确率。

建议下一阶段至少补充：

- 50 个以上完整正常项目，用于学习正常分布。
- 20 个以上经过复核的异常或高风险项目。
- 每种主要采购类型至少 10 个项目。
- 每个项目尽量包含 3 个以上投标人。
- 至少保留 20% 的项目作为最终测试集，训练期间完全不使用。

更理想的长期目标是 200 至 500 个完整项目，其中包含可追溯的正常、误报和确认可疑复核结果。

## 七、数据安全

- 真实投标文件只保存在公司授权的本地环境。
- 不提交到公开 Git 仓库。
- 调用外部大模型前先确认公司数据外发政策。
- 身份证、银行账号、个人手机号等字段应脱敏后再发送给第三方服务。
- 训练集、验证集和测试集必须按项目划分，不能按单份文件随机划分。
