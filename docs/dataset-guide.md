# 招投标数据集整理指南

## 1. 数据集分层

项目采用双轨数据体系，不把没有人工确认的真实文件伪造成违规标签。

```text
data/
  training_internal/standard_dataset/   # 真实文件和无标签清单
  processed/                             # 文档解析与 OCR 结果
  analysis/                              # 项目内两两特征与证据
  synthetic_benchmark/                   # 可追溯受控训练/测试基准
  models/                                # 无监督模型和评估摘要
```

## 2. 真实数据规则

- 推荐样本粒度为“项目-投标人文档对”。
- 只把 `role=bid_document` 的文件作为投标文件输入。
- `evaluation_material`、`reference_material`、`tender_material`、`nested_archive` 和 `other` 保留在清单中，但不能当作投标人样本。
- `samples.csv` 的空标签表示真实数据尚未完成项目级人工复核，不应被解释为“正常”。
- 真实数据用于无监督基线、异常排序和人工复核，不用于计算真实准确率。

## 3. 合成基准规则

通过两两分析结果生成 `data/synthetic_benchmark`：

- `clean_pair` 是受控低信号样本，不是现实世界确认正常样本。
- 其他 `synthetic_label` 表示施加的变换类型，例如 `shared_phone`、`high_text_similarity`。
- 不使用 `collusion`、`bid_rigging`、`illegal` 等词作为合成标签。
- 每条数据必须带有来源项目、来源文档对、变换类型和证据字段。
- 训练集和测试集按项目划分，禁止同一项目跨集合泄漏。
- 异常比较必须限定在同一项目内的不同投标人文件之间；同一单位参加多个项目是正常业务现象，跨项目相似度不能直接作为串标、围标或异常证据。跨项目关系只能用于企业历史画像、重复参标统计和后续人工研判。
- 合成指标只能说明模型是否响应受控特征，不能代表真实串标围标识别准确率。

当前 `data/synthetic_benchmark` 使用 `bid-synthetic-benchmark/v2` schema，除实体和文本信号外，还覆盖文件作者、网络或设备指纹、投标账户、文件混装和报价模式等受控场景。上述场景全部限定在同一项目内的不同投标人之间；跨项目重复参标不生成异常标签。

## 4. 真实标注集要求

后续如要报告真实准确率、召回率或 F1，需要由有权限的业务人员基于完整证据进行项目级复核。建议标签至少包含：

```text
confirmed_normal
needs_review
confirmed_irregularity
```

同时记录 `label_basis`、复核人、复核时间和引用页码。审计结论、处罚结果和人工标签来源不能直接作为模型输入特征。

## 5. 安全和隐私

- 原始投标文件和敏感信息只在本地处理。
- 上传 GitHub 或公开数据集前，必须排除真实投标文件、联系人、电话、邮箱、统一社会信用代码和内部项目名称。
- 大模型只接收脱敏后的证据片段，不接收完整压缩包。
- 合成数据中的电话、邮箱、地址和统一社会信用代码使用占位值，不对应真实主体。
