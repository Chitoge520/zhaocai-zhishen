# 开发计划与进度

> 当前竞赛优化实施计划见 `competition-optimization-development-plan.md`。本文件保留历史开发进度。

## 项目目标

构建本地运行的招投标无监督异常线索发现系统，形成“文件导入、解析/OCR、特征计算、异常检测、证据复核、报告导出”的完整闭环。系统输出审计辅助线索，不直接认定违规。

## 阶段 0：工程基线（已完成，2026-07-11）

- 修复项目根目录计算错误
- 建立 `check`、`prepare`、`analyze`、`serve` 统一 CLI
- 建立项目虚拟环境和可编辑安装
- 增加基础单元测试和服务冒烟测试
- 完善依赖分组、README 和本地数据隔离

最新验收结果：M1 验收时 55 项单元测试通过；统一多源数据导入、覆盖率页面、`/api/coverage` 与任务级覆盖率接口已完成。

## 阶段 1：文件解析与统一样本（核心流程已完成）

M1 已完成统一多源审计数据层：CSV/JSONL 记录进入统一 schema，企业跨项目映射到稳定 `bidder_id`，每条记录保留源文件与源行引用，并分别统计文件、报价、IP 和历史关系覆盖率。该层保持无监督路线，不要求人工标签；缺失结构化字段时按能力降级。

已完成：

- 从 `samples.csv` 加载 63 个投标样本
- 支持 DOCX 和文本型 PDF
- 支持扫描 PDF 自动识别
- 接入本地 RapidOCR，并完成 RTX 3080 PaddleOCR GPU 加速
- 增加逐文档缓存、断点续跑、强制重建和匿名进度
- 输出 `documents.jsonl`、`pages.jsonl`、`unsupervised_samples.jsonl`、失败清单和摘要
- 完成 63 份文件快速盘点：13,732 页，全部可读，42 份需要 OCR
- 完成 CPU 多进程调度与 GPU 单进程保护
- 修复 PaddleOCR 长文档显存累积，识别批次降为 16，并按页批次与文档释放 CUDA 缓存
- GPU 回归通过：20 页峰值显存 2.76GB；156 页完整文档峰值 3.28GB、0 失败
- 完成 63 份文件全量 GPU OCR：63 成功、0 失败、13,732 页、原始 OCR 7,872,221 字符，63 个缓存全部有效
- 完成 `ocr-cleanup/v1` 有效内容清洗：分析文本 7,450,481 字符，原始页文本保留用于证据回放

待完成：

- 增加 DOC 转换适配器（当前样本集中没有 DOC 投标样本）
- 增加金额与报价表结构化抽取

## 阶段 2：无监督异常检测（进行中）

已完成：

- 按项目分组的字符 3-gram 哈希 TF-IDF 和余弦相似度
- 投标人、电话、邮箱、统一社会信用代码、联系人、地址和项目编号抽取
- 统一社会信用代码校验码验证、16,000 字符核心实体区域限制和联系人停用词过滤
- 中国固定电话区号与位数校验、真实地址特征过滤、项目公共实体排除
- 项目内投标人短别名与完整公司名归并，同企业分册不生成异常线索
- 不同投标人之间的共享实体与文本相似度综合异常分数
- 输出 `document_entities.jsonl`、`pairwise_similarity.csv`、`anomaly_results.csv` 和分析摘要
- 共享实体对应原文件页码定位，所有结果标记为待复核异常线索
- 完成全量重算与阈值校准：当前保留 1 条高风险待复核线索
- 增加成段重复证据：公共模板片段排除，重复片段仅作为已有线索佐证
- 新增可追溯合成基准：150 条真实两两特征扩展为 2,100 条、14 类受控变换样本，训练/测试按项目隔离
- 训练摘要区分真实无标签评估与合成受控基准评估，避免伪造真实准确率
- 驾驶舱接入 `/api/unsupervised`，展示异常队列、相似文档对、证据页码、实体概览和关系图谱

当前仍可增强：

- 报价接近度、固定比例和异常尾数
- PDF/DOCX 文件作者等元数据复用
- Isolation Forest 或稳健统计综合异常分数
- 基于全量结果完成阈值校准和 Top-K 误报分析
