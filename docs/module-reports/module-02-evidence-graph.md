# 模块二开发报告：异常关系图谱和证据链数据接口

## 1. 模块定位

本模块把原先分散在实体抽取结果、项目内文档比较结果和异常结果 CSV 中的信息，组织成可以直接展示和继续回放的项目关系图谱。

图谱的目标是让评委直观看到“为什么这两家投标人会进入复核范围”，同时保留从关系节点回到文件和异常线索的入口。图谱只做关联发现和证据导航，不把关联自动解释为串标或围标结论。

## 2. 功能介绍

### 2.1 图谱节点

每个节点带有项目边界，避免不同项目之间出现误连接。当前支持：

- 项目
- 投标人
- 投标文件
- 电话
- 邮箱
- 统一社会信用代码
- 联系人
- 地址

实体节点使用项目范围内的稳定 ID；电话和邮箱在图形标签中做了部分脱敏，完整值仍保留在本地结果用于证据回放。

### 2.2 图谱关系

当前关系包括：

- 项目 → 投标人：参与项目
- 投标人 → 投标文件：提交文件
- 投标人 → 实体：共享电话、邮箱、地址等实体
- 投标人 ↔ 投标人：文本相似比较

文本相似关系会携带相似度、异常分数、参与比较的文件 ID、异常线索 ID和证据摘要。

### 2.3 图谱接口

新增接口：

```text
GET /api/evidence-graph
```

接口返回：

```json
{
  "schema_version": "evidence-graph/v1",
  "ready": true,
  "projects": [],
  "nodes": [],
  "edges": [],
  "findings": [],
  "warning": "..."
}
```

### 2.4 前端关系网络视图

前端新增独立的“关系图谱”页面，包含：

- 项目下拉筛选
- 项目、投标人、文件、实体和相似关系数量卡片
- SVG 关系网络
- 红色高风险相似关系线
- 关系与证据摘要列表
- 证据边界提示

页面默认只绘制当前项目中最有代表性的节点和关系，避免 15 个历史项目一次性堆叠导致无法阅读。完整数据仍由接口返回，后续证据回放模块可以按 `finding_id` 精确钻取。

## 6. 已知限制

- 当前前端采用轻量 SVG 展示，不依赖大型图谱前端框架；节点数量很大时只展示当前项目的代表性子图。
- 共享实体本身可能来自公共办公地址、代理机构或模板内容，必须结合文件页码、时间和业务背景复核。
- 当前图谱边已经携带异常线索 ID，但还没有实现点击关系边直接打开左右证据页；该功能将在模块三完成。
