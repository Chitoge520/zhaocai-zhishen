# 模块七开发报告：实体边界修复与模型结果一致性

## 1. 模块目标

解决“主分析页面、关系图谱和报告可能展示不同结果”的一致性问题，同时修复地址实体抽取过长导致的共享地址误报。

本模块继续遵循无监督异常检测定位：系统输出的是异常线索和待复核线索，不直接认定串标、围标或违法违规。

## 2. 问题定位

### 2.1 地址字段边界不完整

原地址表达式会把同一行中的后续“传真、电话、邮箱”等字段一并捕获。例如：

```text
注册地址：上海市浦东新区浦东南路3470号8楼 传真：021-20881123 电话：13812345678
```

在修复前，地址候选可能包含传真和电话内容，导致不同文件的地址实体无法稳定归一化，也可能制造错误的共享地址证据。

### 2.2 关系图谱未加载冻结模型

`/api/unsupervised` 已把规则分数和冻结模型分数合并，但 `/api/evidence-graph` 之前只读取原始 `anomaly_results.csv`。因此模型新触发的线索可能出现在主列表，却没有对应的图谱线索和边上的 `finding_id`。

## 3. 实现内容

### 3.1 地址实体抽取修复

文件：`src/zhaocai_zhishen/unsupervised_analysis.py`

地址匹配现在会在以下字段前停止：

- 传真、电话、联系电话、手机；
- 邮箱、电子邮箱；
- 邮编、邮政编码；
- 联系人；
- 统一社会信用代码；
- 开户银行、银行账号。

换行、中文分号和英文分号仍然作为终止边界。地址本身仍经过长度、地址地名标记和停用词校验。

### 3.2 关系图谱结果统一

文件：

- `src/zhaocai_zhishen/evidence_graph.py`
- `src/zhaocai_zhishen/server.py`

`load_evidence_graph` 新增可选 `model_path` 参数，并通过 `load_unsupervised_results(..., model_path=...)` 读取规则与冻结模型融合后的 `pairs`、`anomalies`。

服务端 `/api/evidence-graph` 现在传入与 `/api/unsupervised` 相同的 `data/models/bid_anomaly_model.json`。

由模型触发而规则未触发的线索，会自动进入图谱的 `findings`，其文本相似边也会带上对应 `finding_id` 和证据摘要。

## 5. 当前效果与边界

本次修改解决的是结果一致性和实体抽取质量问题，不等同于模型已经具备异常招投标的准确识别能力。当前数据没有项目级确认标签，仍不能计算准确率、召回率或违规概率。

对于下一次上传的项目，系统可以完成：

1. 从压缩包中整理和识别投标文件；
2. 抽取电话、邮箱、地址、统一社会信用代码、联系人等实体；
3. 计算项目内文件对的相似度和无监督异常分数；
4. 将规则线索与冻结模型触发结果合并；
5. 在关系图谱、证据回放和报告中使用同一组待复核线索。

系统仍不能仅凭这批文件直接证明串标、围标或违法违规，最终判断需要人工复核原文、页码、报价结构和外部业务证据。

## 6. 下一步建议

- 增加报价表和关键数字结构解析，补足目前只有文本和实体特征的不足；
- 增加 PDF/DOCX 元数据和作者/生成软件特征，并区分扫描件与可编辑文件；
- 按项目划分验证集，收集复核状态，统计 Top-K 线索有效率；
- 对唯一共享实体和模型极端分数优先建立证据回放演示样例。
