## 5. 安全基线

Git 只允许保存：

- 源代码和测试；
- 公开说明文档；
- 不含真实主体信息的聚合基线；
- `data/.gitkeep` 数据目录占位文件。

Git 不允许保存：

- 原始投标文件和内部压缩包；
- OCR 正文、项目编号、投标人和联系方式；
- 分析明细、任务目录、日志和数据库；
- 模型权重、推理产物、密钥和本地配置。

`docs/baselines/competition-m0-baseline.json` 只含聚合数字、版本和汇总文件摘要哈希。

## 7. M1 输入契约

M1 的统一多源数据层以 `bid-audit/v1` 为首个主版本，第一批表为：

1. `projects.csv`；
2. `bidders.csv`；
3. `bids.csv`；
4. `bid_items.csv`；
5. `submission_events.csv`；
6. `bidder_project_history.csv`；
7. `review_findings.csv`。

M1 实施必须满足：

- 项目、投标人和投标记录主键稳定；
- 缺失 IP、设备、报价或历史数据时允许降级，不伪造字段；
- 每条输入记录保留来源文件、来源表或业务记录引用；
- 导入层不直接产生违规结论；
- 输入 schema 校验失败时按记录隔离，并输出可审计错误清单；
- 真实业务明细继续留在 Git 忽略的数据目录。

## 8. 回滚方式

M0 完成提交使用 Git 标签 `competition-m0-baseline`。后续模块出现不可兼容问题时，可从该标签恢复源代码、测试、文档和 schema 约定；真实数据及处理产物不随 Git 回滚。
