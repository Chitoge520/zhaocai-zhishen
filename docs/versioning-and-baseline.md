# 版本、数据契约与 M0 基线说明

> 基线日期：2026-08-10  
> 比赛发布线：`competition-m0-2026.08`

## 1. 目的

本文件统一应用版本、数据契约版本、证据结构版本和算法版本的命名规则，避免后续模块各自定义版本字段。所有输出仍是“待复核异常线索”，版本升级不改变这一业务边界。

代码中的权威常量位于 `src/zhaocai_zhishen/versioning.py`。新模块不得在业务代码中散落重复的版本字符串。

## 3. 命名规则

### 3.1 Schema 版本

格式：

```text
<业务域>/<主版本>
```

示例：

```text
bid-audit/v1
bid-audit-evidence/v1
bid-audit-baseline/v1
```

规则：

- 新增可选字段不提升主版本；
- 删除字段、改变字段语义或改变主键规则时提升主版本；
- 读取端应拒绝无法识别的主版本，不能静默猜测字段含义；
- 迁移程序必须记录来源版本和目标版本。

### 3.2 算法版本

格式：

```text
<业务域>-<算法族>/<主版本>
```

当前值：

```text
bid-audit-unsupervised/v1
```

以下变化必须形成新的算法版本或比赛发布版本：

- 风险分数公式、特征权重或阈值发生变化；
- 项目隔离、公共模板排除或投标人归并规则发生变化；
- 新增会直接触发风险线索的主信号；
- 模型训练样本范围或冻结模型发生变化。

## 5. 基线清单

机器可读清单位于：

```text
docs/baselines/competition-m0-baseline.json
```

重新生成命令：

```powershell
$env:PYTHONPATH='src'
.venv/Scripts/python.exe -m zhaocai_zhishen baseline --tests 46
```

生成器只读取汇总文件并输出：

- 聚合数量；
- schema 和算法版本；
- 汇总产物 SHA-256；
- 测试质量门；
- 数据与结论边界。

不会写入真实文件名、投标人、项目编号、联系方式、原文、本地绝对路径或模型中的项目列表。

## 6. Git 与敏感数据边界

以下内容不得进入版本控制：

- `data/` 下除 `.gitkeep` 外的真实数据和处理产物；
- 原始投标文件、压缩包、表格和报告导出物；
- OCR 正文、缓存、日志、PID、数据库和临时文件；
- 本地模型权重和推理产物；
- API 密钥、`.env` 和本地工具配置目录。

Git 中只保留源代码、测试、公开文档、脱敏聚合基线和数据目录占位文件。

## 7. 后续模块要求

从 M1 开始，每个持久化输出至少记录：

```json
{
  "schema_version": "bid-audit/v1",
  "algorithm_version": "bid-audit-unsupervised/v1",
  "generated_at": "ISO-8601 时间",
  "source_snapshot": "输入快照或摘要哈希"
}
```

证据节点、风险线索和报告还必须记录可回溯引用；无法回溯到原始文件、页码或业务记录的信号不能进入正式高风险清单。
