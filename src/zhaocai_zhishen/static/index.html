处理链路

1. 文件识别区分招标、投标、评审及参考材料
2. 本地解析GPU OCR 与结构化文本
3. 特征分析实体、相似度和项目内比较
4. 冻结模型无监督异常排序
5. 大模型辅助脱敏证据片段解释
6. 人工复核回到原文件核对页码

使用边界

系统输出的是异常线索和待复核线索，不能直接认定串标、围标或其他违规行为。

新项目至少需要包含两个投标人的投标文件，只有招标文件无法形成投标人之间的异常比较。

历史数据集

当前历史项目只用于模型训练、验证和基线回放。异常比较严格限定在同一项目内；同一单位跨项目参标属于正常业务关系，不会直接计入异常分数。

降级分析边界

缺少报价

仍可执行文本相似度、实体复用与项目内异常排序；不输出报价聚类相关证据。

缺少 IP

仍可执行文档和报价分析；不把“未提供网络日志”误判为低风险。

身份关联键

全局 bidder_id 用于跨项目身份映射，本身不是围标串标证据；信用代码冲突进入质量问题并等待人工核验。

模型训练

当前模型是无监督异常排序基线，不输出违规概率。模型只比较同一项目中的不同投标文件；同一单位出现在多个项目中只用于历史画像，不作为串标或围标证据。
